microsoft.scom.notification_channel module – Manage SCOM notification channels.

Note

This module is part of the microsoft.scom collection (version 2.0.0).

It is not included in ansible-core. To check whether it is installed, run ansible-galaxy collection list.

To install it, use: ansible-galaxy collection install microsoft.scom. You need further requirements to be able to use this module, see Requirements for details.

To use it in a playbook, specify: microsoft.scom.notification_channel.

New in microsoft.scom 2.0.0

Synopsis

  • Creates or removes a SCOM notification channel used to deliver alert notifications.

  • Supports SMTP (email), command, IM (instant message), and SMS channel types.

  • Once created, a channel cannot be updated in place. To change its settings, remove it with state=absent and recreate it with state=present.

Requirements

The below requirements are needed on the host that executes this module.

  • Must execute on the SCOM Management Server via WinRM

  • SCOM Operations Console installed on the target host (provides the OperationsManager PowerShell module or the legacy Microsoft.EnterpriseManagement PSSnapins)

  • SCOM 2012 R2, 2016, 2019, or 2022

  • SCOM Operators role (minimum) for the executing account

Parameters

Parameter

Comments

allow_duplicate_create

boolean

When true, creates a new channel even if one with the same display_name already exists.

Use this when you intentionally want multiple channels with the same display name.

When false, an existing channel with the same display name is left unchanged.

Only applies when state=present.

Choices:

  • false ← (default)

  • true

allow_duplicate_delete

boolean

When true, removes all channels matching display_name if multiple exist.

When false, the module fails if more than one channel matches display_name, preventing accidental bulk deletion.

Only applies when state=absent.

Choices:

  • false ← (default)

  • true

anonymous

boolean

When true, the SMTP server accepts anonymous (unauthenticated) connections.

When false, Windows Integrated Kerberos authentication is used.

Choices:

  • false ← (default)

  • true

application_path

string

The full path to the executable to run for a command channel.

Required when channel_type=command and the channel is being created.

argument

string

The command-line arguments passed to the command channel executable.

backup_smtp_servers

list / elements=string

An ordered list of backup SMTP servers used when the primary server is unavailable.

Added to smtp_server when state=present.

Default: []

body

string

The message body template for SMTP, IM, and SMS channels.

Required when channel_type is smtp, im, or sms.

Should not be empty for these channel types.

body_as_html

boolean

Whether the SMTP message body is sent as HTML.

Choices:

  • false ← (default)

  • true

channel_type

string

The type of notification channel to create.

Required when state=present.

Choices:

  • "smtp"

  • "command"

  • "sms"

  • "im"

description

string

A free-text description for the channel.

display_name

string / required

The display name of the notification channel.

Used as the identity for removal and to detect whether the channel already exists.

encoding

string

The character encoding used for the message (for example utf-8).

im_authentication

string

The SIP authentication protocol used by the IM channel.

ntlm uses Windows Integrated NTLM authentication (default).

kerberos uses Windows Integrated Kerberos authentication.

Choices:

  • "ntlm" ← (default)

  • "kerberos"

im_port

integer

The IM server port.

im_protocol

string

The SIP transport protocol used by the IM channel.

tcp uses plain TCP (default, port 5060).

tls uses TLS (default port 5061).

Choices:

  • "tcp" ← (default)

  • "tls"

im_server

string

The IM server host name.

Required when channel_type=im and the channel is being created.

im_user

string

The IM URI of the sending user (for example sip:scom@contoso.com).

Required when channel_type=im and the channel is being created.

return_address

string

The return (sender) address shown in the From: header of notification emails. Matches the Return address field in the SCOM console.

Required when channel_type=smtp and the channel is being created.

smtp_port

integer

The SMTP server port. Defaults to the SCOM default (25) when omitted.

smtp_server

string

The SMTP server host name.

Required when channel_type=smtp and the channel is being created.

state

string

present ensures the channel exists, creating it if necessary.

absent removes the channel if it exists.

Choices:

  • "present" ← (default)

  • "absent"

subject

string

The subject line template for SMTP notifications.

working_directory

string

The working directory for the command channel executable.

Notes

Note

  • These modules must run directly on the SCOM Management Server via WinRM. The OperationsManager PowerShell module is only installed on hosts where the SCOM Operations Console has been installed, and the SDK auto-connects to the local Management Group on import. Running on any other Windows host will fail.

  • Supported SCOM versions: 2012 R2, 2016, 2019, 2022.

  • The account executing this module must hold at minimum the SCOM Operators role on the Management Group. Administrative operations (e.g. importing management packs) require the SCOM Administrators role.

Examples

- name: Create an SMTP notification channel
  microsoft.scom.notification_channel:
    display_name: "Ops Email Channel"
    description: "Email channel for operational alerts"
    channel_type: smtp
    smtp_server: "smtp.contoso.com"
    smtp_port: 2525
    return_address: "scom@contoso.com"
    encoding: "US-ASCII"
    backup_smtp_servers:
      - "bck.server.com"
    subject: "SCOM Alert: $Data/Context/DataItem/AlertName$"
    body: "$Data/Context/DataItem/AlertDescription$"
    body_as_html: true
    anonymous: true

- name: Create a second SMTP channel with the same display name
  microsoft.scom.notification_channel:
    display_name: "Ops Email Channel"
    channel_type: smtp
    smtp_server: "smtp.contoso.com"
    return_address: "scom@contoso.com"
    body: "$Data/Context/DataItem/AlertDescription$"
    allow_duplicate_create: true

- name: Create an IM (instant message) notification channel
  microsoft.scom.notification_channel:
    display_name: "Ops IM Channel"
    description: "IM channel for operational alerts"
    channel_type: im
    im_user: "sip:scom@contoso.com"
    im_server: "sipserver.contoso.com"
    im_port: 5061
    im_authentication: kerberos
    im_protocol: tls
    encoding: "utf-8"
    body: "$Data/Context/DataItem/AlertName$"

- name: Create a Command notification channel
  microsoft.scom.notification_channel:
    display_name: "Run Remediation Script"
    channel_type: command
    application_path: 'C:\Scripts\remediate.cmd'
    argument: "/alert:$Data/Context/DataItem/AlertId$"
    working_directory: 'C:\Scripts'

- name: Create an SMS notification channel
  microsoft.scom.notification_channel:
    display_name: "Ops SMS Channel"
    description: "SMS channel for critical alerts"
    channel_type: sms
    encoding: "Unicode"
    body: "$Data/Context/DataItem/AlertName$"

- name: Remove a notification channel
  microsoft.scom.notification_channel:
    display_name: "Ops Email Channel"
    state: absent

- name: Remove duplicated notification channels by display name
  microsoft.scom.notification_channel:
    display_name: "Ops Email Channel"
    allow_duplicate_delete: true
    state: absent
