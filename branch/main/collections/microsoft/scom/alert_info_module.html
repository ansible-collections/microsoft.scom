microsoft.scom.alert_info module – Retrieve information about SCOM alerts.

Note

This module is part of the microsoft.scom collection (version 2.0.0).

It is not included in ansible-core. To check whether it is installed, run ansible-galaxy collection list.

To install it, use: ansible-galaxy collection install microsoft.scom. You need further requirements to be able to use this module, see Requirements for details.

To use it in a playbook, specify: microsoft.scom.alert_info.

Synopsis

  • Returns a list of SCOM alerts matching the specified filter criteria.

  • Supports filtering by raw SCOM criteria string, severity, resolution state, and monitoring object display name.

  • This is an info module — it never makes changes and always returns changed=false.

Requirements

The below requirements are needed on the host that executes this module.

  • Must execute on the SCOM Management Server via WinRM

  • SCOM Operations Console installed on the target host (provides the OperationsManager PowerShell module or the legacy Microsoft.EnterpriseManagement PSSnapins)

  • SCOM 2012 R2, 2016, 2019, or 2022

  • SCOM Operators role (minimum) for the executing account

Parameters

Parameter

Comments

criteria

string

A raw SCOM criteria expression used to filter alerts, e.g. (ResolutionState = '0' AND (Severity = ‘2’)).

Combined with AND with the severity, resolution_state, and monitoring_object filters when those are also specified.

monitoring_object

string

Filter alerts by a substring match on the monitoring object’s display name.

resolution_state

string

Filter alerts by resolution state.

new returns only unactioned alerts (ResolutionState 0).

closed returns only closed alerts (ResolutionState 255).

any or omitting the parameter returns alerts in all states.

Choices:

  • "new"

  • "closed"

  • "any"

severity

string

Filter alerts by severity level.

When omitted, alerts of all severity levels are returned.

Choices:

  • "information"

  • "warning"

  • "critical"

Notes

Note

  • These modules must run directly on the SCOM Management Server via WinRM. The OperationsManager PowerShell module is only installed on hosts where the SCOM Operations Console has been installed, and the SDK auto-connects to the local Management Group on import. Running on any other Windows host will fail.

  • Supported SCOM versions: 2012 R2, 2016, 2019, 2022.

  • The account executing this module must hold at minimum the SCOM Operators role on the Management Group. Administrative operations (e.g. importing management packs) require the SCOM Administrators role.

Examples

- name: Get all new critical alerts
  microsoft.scom.alert_info:
    severity: critical
    resolution_state: new
  register: critical_alerts

- name: Get alerts matching a custom SCOM criteria string
  microsoft.scom.alert_info:
    criteria: "(TimeRaised > '2026-01-01 00:00:00')"

- name: Get all open warnings for a specific server
  microsoft.scom.alert_info:
    severity: warning
    resolution_state: new
    monitoring_object: web-server-01

- name: Get all alerts regardless of state
  microsoft.scom.alert_info:
    resolution_state: any
